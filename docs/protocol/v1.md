# Harness Shell Sidecar Protocol v1

## Transport

Tauri Core and the Python Sidecar exchange UTF-8 JSON over private stdin/stdout pipes. Each message uses one ASCII length header followed by the exact number of JSON bytes:

```text
Content-Length: <UTF-8 JSON byte length>\r\n
\r\n
<JSON payload>
```

The header name is case-sensitive. No second header, duplicate header, signed length, whitespace suffix or transfer encoding is accepted.

## Hard limits

| Setting | Value |
| --- | ---: |
| Protocol version | `1` |
| Maximum header | `8_192` bytes |
| Maximum JSON payload | `1_048_576` bytes |
| Outbound queue capacity | `64` frames |
| Heartbeat interval | `5_000` ms |
| Heartbeat timeout | `15_000` ms |
| Graceful shutdown timeout | `3_000` ms |

Payload length is measured after UTF-8 encoding. Binary data only enters a method-specific bounded canonical Base64 field, such as PTY output/input; Protocol v1 has no generic `artifact_id` fallback.

## Envelope

Every JSON payload is an object with exactly these fields:

```text
protocol_version: 1
message_type: request | response | event | error | cancel | heartbeat
request_id: UUID string
task_id: UUID string | null
workflow_run_id: UUID string | null
sequence: positive integer
timestamp: RFC 3339 timestamp with timezone
sensitivity: normal | secret
payload: JSON object
```

`task_id` and `workflow_run_id` are null only during process bootstrap or when no task exists. Unknown envelope fields are a terminal protocol violation.

## Ordering and buffering

Each sender owns one sequence beginning at `1`. The value increases by exactly one for every frame written by that sender, including heartbeat and error frames. The receiver never combines, discards or reorders complete frames. A duplicate, regression or gap is terminal for the current Sidecar process.

The writer has one bounded FIFO queue of 64 frames. A full queue applies backpressure to the producer. It does not drop or merge messages.

After initialization, protocol v1 permits multiple correlated application requests to be active. Each request keeps its own `request_id`; responses and errors repeat that ID even when they complete out of order. Heartbeats are handled independently of application request completion. More than 16 active application requests is rejected with `REQUEST_CAPACITY_EXCEEDED`, and duplicate active IDs are rejected with `DUPLICATE_REQUEST_ID`.

## Sensitive frames

`sensitivity=secret` marks a frame whose payload may contain runtime key material or credentials. Logs, Trace and audit metadata may record only envelope identifiers, message type, sequence and byte size. They must not serialize, format or copy the payload body.

Sensitive frames use the same pipe and codec as normal frames; the marker restricts observation and persistence rather than claiming transport encryption. The pipes are private child-process handles owned by Tauri Core.

In M2, `ssh.connect` and `pty.write` are always secret. `host_key.inspect` is normal for a direct endpoint, but is secret for a target reached through ProxyJump because authenticating the jump requires its credential. Connection CRUD, PTY open/resize/close, and Host Key confirm/replace frames never contain credential plaintext.

## M2 SSH methods

The M2 allowlist is exact:

```text
connections.list
connections.get        # Tauri Core internal; never WebView-callable
connections.create
connections.update
connections.delete
host_key.inspect
host_key.confirm
host_key.replace
ssh.connect
ssh.disconnect
pty.open
pty.write
pty.resize
pty.close
```

`connections.list`, `connections.get`, `connections.create`, and `connections.update` return an integer `version` in the inclusive JS-safe range `1..9007199254740991`. Creation starts at `1`; every successful profile update atomically increments the stored value by exactly one. `updated_at` remains display metadata and is not a concurrency or credential-snapshot token. Version exhaustion fails with `CONNECTION_VERSION_EXHAUSTED` and leaves the row unchanged.

`ssh.connect.params` includes `connection_id`, the exact numeric `profile_version` returned by `connections.get`, and exactly one authentication shape: `password_b64`, or `private_key_b64` plus optional `passphrase_b64`. A proxied request also carries a nested `jump` object with the jump `connection_id`, its exact numeric `profile_version`, and its own independent authentication shape. The Sidecar strictly rejects missing, non-integer, out-of-range, or legacy `profile_updated_at` snapshots, then checks both versions and the declared jump identity before network I/O. A mismatch fails with `CONNECTION_PROFILE_CHANGED`. All secret byte fields use canonical base64 and are zeroized after the handler completes.

`ConnectionStatus.trusted_fingerprint_sha256` is non-null only when inspection reports `HOST_KEY_CHANGED`; it lets the UI display and submit the exact old fingerprint for compare-and-swap replacement without exposing public-key or credential secrets.

No WebView command maps directly to raw Agent exec or Agent SFTP. The old Sidecar-internal Agent exec/SFTP implementation has been removed; the experimental ReAct backend described below instead binds its only command tool to the caller-selected connected SSH Session. User-operated manual SFTP is exposed only through 21 main-window Tauri commands and exactly 24 private `manual_sftp.*` methods; Rust owns native picker paths, canonical local identities, DPAPI-protected coordination records, transfer bytes and the private Sidecar calls. The WebView never receives a local absolute path, file content, raw Protocol frame, credential, runtime key or mutable snapshot authority.

The private manual SFTP method allowlist is exact:

```text
manual_sftp.open
manual_sftp.list.begin
manual_sftp.list.next
manual_sftp.list.close
manual_sftp.lstat
manual_sftp.readlink
manual_sftp.realpath
manual_sftp.sha256
manual_sftp.upload.preflight
manual_sftp.upload.begin
manual_sftp.upload.chunk
manual_sftp.upload.finish
manual_sftp.upload.abort
manual_sftp.download.begin
manual_sftp.download.chunk
manual_sftp.download.finish
manual_sftp.download.abort
manual_sftp.mkdir
manual_sftp.rename
manual_sftp.remove
manual_sftp.delete.preflight
manual_sftp.delete.execute
manual_sftp.recovery.inspect
manual_sftp.recovery.execute
```

Only `manual_sftp.upload.chunk` and `manual_sftp.download.chunk` use `sensitivity=secret`; both carry bounded canonical Base64 bytes. Listings use an opaque ID plus exact monotonic sequence and stop at 200 entries per batch / 50,000 observed entries. Every mutation uses a fresh Rust-selected operation ID; Rust acquires canonical no-follow snapshots and regular-file hashes immediately before dispatch, and Python rechecks them immediately before remote mutation. Known typed failures such as permission denial, unsupported atomic rename and cross-filesystem move remain trustworthy terminal errors with stable codes. A typed error may additionally carry only `operation_state=cleanup_required|outcome_unknown` when Python has already persisted that exact non-terminal state; Rust must retain the matching local journal record. Only an untrusted dispatch outcome becomes `SFTP_*_OUTCOME_UNKNOWN`; cleanup ambiguity becomes `SFTP_*_CLEANUP_REQUIRED`, and neither is replayed automatically.

Manual SFTP recovery is explicit and never replays the uncertain request. `manual_sftp.recovery.execute.params` is exactly `{recovery_id, action, operation_id}`. Rust selects `operation_id`; Python rejects it unless it differs from `recovery_id` and every persisted remote operation identity, then uses that exact ID for any `delete_temp`, `continue_delete`, or `restore_tombstone` mutation. Rust persists its local recovery coordination ID together with the real remote operation ID so restart inspection addresses the exact Sidecar record without guessing.

Download `.part` recovery is Rust-local rather than a private Protocol method. Rust derives the part name from a DPAPI-protected record, validates the no-follow locked handle and mandatory SHA-256, and exposes only the safe host label, target basename, state and allowlisted actions. Inspect, Keep and Open local folder do not start or contact Python; no local path is serialized to the WebView.

Recursive-delete preflight also uses a caller-selected durable identity: `manual_sftp.delete.preflight.params` is exactly `{operation_id, ssh_session_id, path}`. Rust persists the local journal record before dispatch; Python rejects a reused `operation_id` and uses the accepted ID for the encrypted plan and remote operation record. A successful preflight keeps the local record until execution reaches a trustworthy terminal state, while reply loss or shutdown can inspect the same remote identity after restart without replaying preflight.

Sidecar events accepted by the Rust Broker are limited to `ssh.connection.status`, `ssh.pty.output`, `ssh.pty.closed`, and `manual_sftp.operation.progress`. The three SSH events keep the `ssh://event` projection. Manual SFTP progress is strictly decoded into the non-secret `manual-sftp://operation-state` projection; unknown fields, `cancellable=true`, and unknown event names fail closed. Failure to emit a legal typed progress projection is observational only: Rust records a bounded path-free diagnostic and does not alter, abort or replay the operation. A PTY output event carries base64 bytes in `data_b64`; decoded chunks are at most `32_768` bytes and `stream_sequence` increases by one per PTY session.

Manual SFTP Python channel open/close and metadata/simple-mutation requests use a 15-second request deadline. Rust mutation dispatch and transfer-chunk requests use a 30-second deadline; Python listing batches and transfer chunks likewise use 30 seconds. Complete SHA-256 and recursive work use a 60-second no-progress deadline without an arbitrary total wall-clock cap. Timeout never becomes retry or user cancellation. A Rust caller timeout does not cancel the already-dispatched actor request: the single mutation actor waits for its real result, converges the journal, and only then runs any queued transfer abort, so forward mutation and cleanup cannot overlap.

Recovery records freeze the connected profile's numeric `version`, safe `display_name`, target Host Key fingerprint, and optional ProxyJump connection/version/fingerprint tuple. Recovery may use only one live SSH Session with that exact authenticated identity; reusing the same `connection_id` after editing a profile or replacing a Host Key fails closed. A persisted late terminal receipt remains inspectable even after it disappears from the non-terminal recovery list.

For SFTP v3, AsyncSSH maps any non-zero rename flags to OpenSSH `posix-rename@openssh.com`, which has overwrite semantics. Therefore an absent destination uses standard v3 no-clobber rename (`flags=0`); an existing destination confirmed by the user uses atomic overwrite flags. SFTP v5+ uses `FXR_ATOMIC` for absent destinations and `FXR_ATOMIC | FXR_OVERWRITE` for confirmed overwrite. A destination which appears after an absent snapshot fails with `SFTP_TARGET_CHANGED`; no weaker retry occurs.

## Experimental M3 ReAct Agent methods

The experimental Agent backend adds exactly six private Sidecar methods. It adds no streaming Protocol event and no raw shell or SFTP method:

```text
agent.api_configs.list
agent.api_configs.get
agent.api_configs.create
agent.api_configs.update
agent.api_configs.delete
agent.turn.run
```

The five `agent.api_configs.*` requests and responses use `sensitivity=normal`. A model API configuration contains `api_config_id`, `display_name`, explicit `api_type`, normalized `base_url`, `model`, opaque `api_key_secret_ref`, `enabled`, `created_at`, and `updated_at`; it never contains API key plaintext. `api_type` is exactly `CHAT_COMPLETIONS` or `RESPONSES`. There is no automatic endpoint probing or fallback between the two APIs.

`agent.turn.run` must use `sensitivity=secret`. Its exact `params` fields are `conversation_id`, `ssh_session_id`, `api_config_id`, `api_key_credential_id`, canonical `api_key_b64`, and `user_message`. Rust resolves the API key from Vault only after reading the selected non-secret configuration and sends both the frozen credential identity and secret bytes. Python freezes that complete non-secret configuration at handler entry, then compares the full persisted configuration again after acquiring the per-conversation lock and immediately before creating a Run or doing model work; any field change, deletion, disablement, or credential-reference change fails closed with the corresponding `MODEL_API_CONFIG_*` code. The same boundary requires the declared `ssh_session_id` to remain present in the authoritative connected Session registry, otherwise it returns `SSH_SESSION_UNAVAILABLE` without creating a Run or calling the model. Secret bytes are decoded only for the request scope, never logged or persisted, and the response is always `sensitivity=normal`.

A successful `agent.turn.run` response is one non-streaming `AgentTurnResult` object:

```text
conversation_id: UUID string
agent_run_id: UUID string
status: COMPLETED | FAILED | LIMIT_REACHED | CANCELLED
final_text: string | null
react_iteration: integer in 0..128
error_code: string | null
```

Each run remains bound to the declared connected `ssh_session_id`. The model may request only the strict `execute_command` tool with exactly one `command` string; it cannot supply or replace a session identity. More than one tool call in a model response fails with `MULTIPLE_TOOL_CALLS_UNSUPPORTED`, an unknown tool fails with `UNKNOWN_TOOL`, invalid arguments fail with `COMMAND_REJECTED_INVALID_ARGUMENTS`, and the fixed direct-danger pattern fails with `COMMAND_REJECTED_DANGEROUS_PATTERN`. The command is passed unchanged to one non-PTY AsyncSSH process, with no retry and a 30-second timeout.

Every tool result returned to the model is a versioned object with exactly `schema_version=1`, `ok`, stable `code`, non-sensitive `message`, and nullable `result`. When present, `result` contains exactly `command`, `exit_code`, `exit_signal`, strict UTF-8 `stdout`, strict UTF-8 `stderr`, `timed_out`, and `duration_ms`. A timeout may include the determined partial output and uses `COMMAND_TIMEOUT`; invalid UTF-8 fails explicitly with `COMMAND_OUTPUT_INVALID_UTF8`. A previous durable AI tool call lacking its matching Tool message is repaired only with a synthetic `PREVIOUS_TOOL_CALL_INTERRUPTED` Tool message linked by the original tool-call ID.

The Agent boundary preserves stable failures instead of substituting fallback behavior. The complete public error-code contract is frozen by `fixtures/agent/public-error-codes-v1.json`; internal repository and lifecycle codes are mapped to `SIDECAR_RUNTIME_FAILED` rather than escaping this boundary. The public codes are:

```text
request: AGENT_NORMAL_FRAME_REQUIRED | AGENT_SECRET_FRAME_REQUIRED | INVALID_REQUEST_PAYLOAD | REQUEST_CANCELLED
api_config: MODEL_API_CONFIG_CHANGED | MODEL_API_CONFIG_DISABLED | MODEL_API_CONFIG_IN_USE | MODEL_API_CONFIG_NOT_FOUND | MODEL_API_CONFIG_PERSISTENCE_FAILED
turn: AGENT_CANCELLED | AGENT_CONVERSATION_NOT_FOUND | AGENT_RESPONSE_TOO_LARGE | AGENT_TURN_FAILED | MODEL_NETWORK_TIMEOUT | MODEL_REQUEST_FAILED | MODEL_RESPONSE_INVALID | REACT_LIMIT_REACHED | SIDECAR_RUNTIME_FAILED | SSH_SESSION_UNAVAILABLE
tool: COMMAND_COMPLETED | COMMAND_EXECUTION_ERROR | COMMAND_OUTPUT_INVALID_UTF8 | COMMAND_REJECTED_DANGEROUS_PATTERN | COMMAND_REJECTED_INVALID_ARGUMENTS | COMMAND_TIMEOUT | MULTIPLE_TOOL_CALLS_UNSUPPORTED | PREVIOUS_TOOL_CALL_INTERRUPTED | SSH_SESSION_LOST | SSH_SESSION_UNAVAILABLE | UNKNOWN_TOOL
```

A normal frame for `agent.turn.run` fails with `AGENT_SECRET_FRAME_REQUIRED`, while a secret frame for any `agent.api_configs.*` method fails with `AGENT_NORMAL_FRAME_REQUIRED`. Missing or disconnected bound sessions fail with `SSH_SESSION_UNAVAILABLE` or `SSH_SESSION_LOST`; other determined command-launch or I/O failures use `COMMAND_EXECUTION_ERROR`. Model request timeouts exhausted after the fixed retry schedule use `MODEL_NETWORK_TIMEOUT`. Observed cancellation uses `AGENT_CANCELLED`. Reaching 128 completed tool iterations ends the run with `REACT_LIMIT_REACHED` and no further model call.

Cancellation is cooperative and introduces no implicit retry. It prevents later model or command dispatch once observed; an in-flight model request or AsyncSSH process is cancelled through its owning runtime operation. The durable run ends as `CANCELLED` rather than claiming completion.

The complete encoded response envelope, including `final_text`, must fit the Protocol v1 `1_048_576` byte JSON limit. AgentService checks a conservative maximum legal envelope before the successful durable terminal transition; an oversized result first transitions its Run from `RUNNING` to `FAILED` with `AGENT_RESPONSE_TOO_LARGE`, then the handler returns that code. Final text is never truncated, summarized, dropped, or moved to an artifact fallback.

Migration `002_m2.sql` still contains `artifact_metadata` as immutable migration history, but no current `ArtifactStore`, Artifact Protocol method, `artifact_id` response, Agent exec, or Agent SFTP runtime uses that table. ## Heartbeats

A heartbeat frame has `message_type=heartbeat` and payload `{"kind":"ping"}` or `{"kind":"pong"}`. Tauri sends a ping every 5 seconds after initialization. The Sidecar returns a pong with a new sender-local sequence. If Tauri receives no valid frame for 15 consecutive seconds, it pauses the runtime with `SIDECAR_HEARTBEAT_TIMEOUT`; it does not restart the Sidecar automatically.

## Cancellation and shutdown

A cancellation frame has a new `request_id` and payload:

```json
{
  "target_request_id": "UUID",
  "reason": "user_requested"
}
```

Cancellation means the application will not start further work for the target request. It does not claim that already-dispatched external work stopped. Cancelling an unknown or completed request returns a typed error and does not alter another request.

A shutdown request uses payload `{"method":"shutdown"}`. The Sidecar acknowledges it, flushes local state and exits within 3 seconds. Tauri may kill the child after that grace period.

## Terminal violations

Malformed headers, invalid UTF-8 or JSON, schema violations, unsupported protocol versions and declared payloads over the hard limit are terminal. The decoder clears buffered bytes before surfacing the error. The process may emit one best-effort typed error only when framing remains trustworthy, then exits or pauses; it never skips bytes to guess a new boundary.

There is no protocol downgrade, alternate stdout format, line-delimited JSON fallback or implicit backend. A peer that cannot use protocol v1 must fail closed.
